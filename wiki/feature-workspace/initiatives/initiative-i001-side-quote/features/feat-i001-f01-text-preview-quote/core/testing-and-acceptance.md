# I001-F01 测试与验收

> 范围：必测用例、验收标准、端到端环境与证据形式、由本 Feature 派生的变更义务。
> 实现契约见 [implementation.md](implementation.md)，内容契约见
> [quote-content-contract.md](quote-content-contract.md)。

## 1. 分层与责任

| 层 | 承载 | 运行方式 | 能证明什么 |
| --- | --- | --- | --- |
| 单元层 | 模板、截断、相对化、白名单、敏感名单、已引用记录、防抖/去重、清理、适配器接缝 | `node --test "code/test/**/*.test.mjs"` | 纯逻辑正确性 |
| 端到端层 | 真实 DSH 侧栏里的划词 → 按钮 → 插入 → 通知 | `node --test "code/test/e2e/**/*.test.mjs"`（需外部浏览器驱动，见 §4） | 浏览器主链路 |
| 人工回归层 | 其他格式零影响 | 人眼逐格式确认 + 截图 | 未破坏既有预览 |

仓库命令只覆盖前两层中的逻辑部分。**任何"已验证"结论都不得只引用 `node --check` /
`node --test` 的通过结果**；浏览器行为必须有端到端证据。

## 2. 单元层必测用例

编号 `U-nn` 与验收标准一一对应。

### U-01 原文块模板

- 输入：单行摘录 `hello`、路径 `notes/a.md`。
- 期望 `text`：`hello\n\n来源：notes/a.md`。
- 断言：逐字相等。

### U-02 保真

- 输入：多行文本，含空行、4 空格缩进、制表符、行内多空格、`\r\n` 行尾。
- 期望：仅行尾归一为 `\n`，其余逐字不变；首尾各一个空行被去掉。
- 反例：不得出现围栏、不得 trim 单行、不得把制表符转空格。

### U-03 截断（行）

- 输入：201 行文本。
- 期望：保留前 200 行 + 一行截断说明 + 空行 + `来源：` 行。

### U-04 截断（字符）

- 输入：单行 9000 字符。
- 期望：硬截到 8000 字符 + 截断说明 + 空行 + `来源：` 行。

### U-05 截断（先到先截）

- 输入：50 行 × 400 字符（共 20 000 字符，50 行）。
- 期望：按字符先命中 → 回退到最后一个使总长 ≤ 8000 的行边界，行数 < 50，带说明。

### U-06 未截断不带说明

- 输入：10 行短文本。
- 期望：不出现截断说明。

### U-07 指针块模板

- 前置：同一 `sessionId` + 同一路径已有一条记录。
- 期望 `text`：`已引用过：notes/a.md\n原文未重复贴出；需要时请重新读取该文件。`
- 断言：不含摘录原文、不含 `来源：`。

### U-08 已引用记录

- 首次查询 → 未命中；插入成功后查询 → 命中。
- 第二次同路径 → 指针块。
- 同路径不同 `sessionId` → 各自独立。
- 插入返回 `false` → 不写记录。
- 容量：写入 501 条后，最早一条被淘汰。

### U-09 路径相对化

- 工作区内绝对路径 + 根 → 相对路径，`/` 分隔。
- 大小写不同的根前缀（Windows） → 仍能相对化。
- 工作区外路径 → 原样（归一后）。
- 根为空 → 原样（归一后）。
- 反斜杠 → `/`。

### U-10 格式白名单

- 命中：`a.md`、`b.MD`、`c.ts`、`d.json`、`e.yml`、`f.log`、`g.csv`、`.env`（精确名）。
- 不命中：`x.pdf`、`x.png`、`x.xlsx`、`x.docx`、**`x.html`**、**`x.htm`**、`Makefile`
  （无扩展名且不在精确名表）、空文件名。
- 断言：白名单常量是唯一声明点（测试直接 import/读取该常量，不复制清单）。

### U-11 敏感名单

- 命中：`.env`、`.env.local`、`.env.example`、`server.pem`、`tls.key`、`id_rsa`、
  `aws_credentials.json`、`client_secret.txt`、`store.pfx`、`store.p12`。
- 不命中：`notes.md`、`env.md`、`keyboard.ts`。
- 断言：命中只返回"需警示"标志，不影响是否可引用。

### U-12 防抖（按钮状态）

- 连续 5 次选区变化，间隔 < 350ms → 状态定稿只发生 1 次，且在最后一次变化后 350ms。
- 间隔 > 350ms 的变化 → 各自定稿。
- `dispose()` 后不再有任何定稿调用。

### U-13 点击去重

- 处理中再次点击 → 只执行 1 次插入。
- 处理结束后再点 → 正常执行（产生指针块，见 U-08）。

### U-14 失败分支

- `mounted` 为空 → 按钮置灰；强制触发点击在 actions 层仍产生一条 `error`（注入的 `notify`
  收到），但插件接线下该状态没有可投递通道，真实表现为静默（见 `implementation.md` §8.1）。
- `sessions.scope()` 返回 `undefined` → 按钮置灰；强制点击在 actions 层产生一条 `error`，
  接线同样无通道，真实表现为静默。
- 选区仅空白 → 按钮置灰；强制点击 → `error` 通知。
- `insertQuote` 返回 `false` → `error` 通知，未写记录，按钮恢复可用。
- 适配器 `readSelection` 抛错 → `error` 通知，异常不外泄。

### U-15 清理

- 装 → 卸一次后：`selectionchange` / `pointerup` / `keyup` 监听计数归零；定时器归零；
  适配器注册归零；locale 字典归零；位点注册归零。
- 以 stub 计数断言，不依赖真实 DOM。

### U-16 适配器接缝

- 注册两个 `id` 相同的适配器 → 抛错。
- 注销后 `match` / `readSelection` 不再被调用。
- 注册一个假适配器（`match` 只认 `.fake`，`readSelection` 返回固定文本）→ 核心无需
  修改即产出正确的原文块；证明 F02 只加适配器可行。

### U-17 本地化

- `zh` 与 `en` 字典键集合完全一致，无缺失、无多余。
- 断言 `来源：`、截断说明、指针块文案**不**出现在字典中（它们是内容而非 UI 文案）。

### U-18 `summary` 契约

- 原文块：`label` = basename，`title` = 路径，`detail` 含行数与截断标记，`body` = 摘录。
- 指针块：`detail` = `已引用过`，`body` = 指针文案。
- 断言：`summary` 不含 `text` 之外的信息。

### U-19 跨预览体选区

- 前置：两个文本预览体各在一个窗格（或两个不同 `occurrence`）。
- 输入：选区锚点落在 A 的 `occurrence`，终点（`focusNode` / `range.endContainer`）落在 B。
- 期望：A 的按钮置灰；强制点击只产生一条 `error`，且不插入、不写已引用记录。
- 反例（护栏）：锚点与终点同属 A 时必须仍可用，防止过度置灰。
- 归属：AC-8（评审 H-1）。

## 3. 端到端层必测用例

编号 `E-nn`。全部在独立 profile 与独立端口上运行。

- **E-01 首次引用闭环**：独立实例 → 打开工作区内 `notes/a.md` → 划选一段 → 等
  350ms → 按钮可用 → 点击 → 输入框出现引用块，内容为"摘录 + 空行 + `来源：notes/a.md`"。
- **E-02 同文件再引**：同一文件再划另一段 → 点击 → 出现指针块，不含原文。
- **E-03 跨文件独立**：打开 `notes/b.md` → 划词 → 点击 → 出现原文块（未被文件 A 的
  记录影响）。
- **E-04 其他格式零影响**：依次打开 `.pdf`、`.png`、`.xlsx`、`.docx`、`.html` →
  按钮均不出现；预览表现与未安装插件时一致（同视口截图对比）。断言前必须在同一页先做
  **正向对照**（白名单内的 `.md` 确实出现按钮），否则渲染延迟会造成假通过（评审 W-5）。
- **E-05 敏感文件**：运行时在临时工作区生成名为 `.env` 的夹具（内容为合成占位，如
  `DEMO_TOKEN=placeholder`）→ 打开 → 划词 → 点击 → 原样插入 + **恰好一条** `info` 警示
  （断言通知条数与层级，不只匹配文案）。
  - 环境例外（评审 W-3，已核实）：Files 页不列出以 `.` 开头的隐藏项，浏览器层无法打开
    `.env`。因此浏览器层改用同样命中敏感名单且在白名单内的 `notes/secret.md`，并额外用
    `notes/server.pem`（敏感名但不在白名单）验证"不出现按钮"；`.env` 的精确名分支由单元层
    U-10、U-11 覆盖。`.env` 的浏览器用例记为**不适用**，**不得**计为通过。
- **E-06 无选区**：打开文本预览，不划词 → 按钮置灰。
- **E-07 切 tab 后选区失效**：划词 → 切到另一个预览 tab → 切回 → 按钮状态符合
  "严格同一预览体"规则（旧选区不再可用）。
- **E-08 停用清理**：停用插件 → 按钮消失 → 重新划词无任何反应 → 控制台无报错。
- **E-09 双窗格跨预览体选区**：两个窗格各开一个文本预览 → 从 A 拖选到 B → A 的按钮不可用。
  环境不支持稳定双窗格时记为**不适用**并写明原因，不得计为通过；此时 U-19 是该规则的唯一
  证据（评审 H-1）。

## 4. 端到端环境与证据形式

### 4.1 环境

| 项 | 值 |
| --- | --- |
| DSH profile | `side-quote-verify`（独立，由自带 web 模板新建） |
| 端口 | `3181`（**不得**使用用户 live 的 `3081`） |
| DSH_HOME | 临时目录（`%TEMP%\side-quote-e2e\dsh-home`），不使用用户的真实 `%USERPROFILE%\.dsh` |
| 工作区 | 临时目录，内含 `notes/a.md`、`notes/b.md` 与各格式样本 |
| 浏览器 | 外部驱动的 Chromium 实例（由验收 session 提供 CDP 端点） |

端口 3181 的环境例外（实现期实测，`2026-11-16`）：

- 本机 Windows TCP 保留区间包含 `3119–3218`（`netsh interface ipv4 show excludedportrange
  protocol=tcp` 可复现），因此 `3181` 触发 `listen EACCES`，不可绑定。
- 该端口的**要求意图**是"独立实例、与用户 live 的 `3081` 分离"。意图不变，取值替换为
  `34181`（同在保留区间之外），并在证据记录中写明替换原因与 `netsh` 原始输出。
- 硬要求仍然成立：不得使用 `3081`、不得改动用户 live profile 与其会话存储。使用临时
  `DSH_HOME` 是为了更强地满足这一条，不改变 profile 名仍为 `side-quote-verify`。
- `SIDE_QUOTE_E2E_BASE_URL` 的默认值保持 `http://127.0.0.1:3181`（契约默认）；实际执行时由
  验收 session 显式传入真实端口。

硬要求：

- 全程不终止、不重启、不修改用户正在使用的 `dsh web` 进程与其 profile。
- 实验代码只进入 `side-quote-verify`；验收结束后按记录回收，不残留到 live profile。
- 不得把插件装进 live profile 以"顺便"取证。

### 4.2 驱动方式（保持零依赖）

`code/test/e2e/**/*.test.mjs` 是普通 `node:test` 文件，通过下列环境变量连接已存在的
外部实例，**不自带浏览器驱动依赖、不新增 `dependencies`**：

| 变量 | 含义 | 未设置时 |
| --- | --- | --- |
| `SIDE_QUOTE_E2E_BASE_URL` | DSH 实例地址（含启动 token），默认 `http://127.0.0.1:3181` | 测试 `skip`，理由写明"未提供 DSH 实例" |
| `SIDE_QUOTE_E2E_CDP` | 浏览器 CDP 端点，接受 `ws://…` 或 `http://host:port` | 测试 `skip`，理由写明"未提供浏览器驱动" |
| `SIDE_QUOTE_E2E_EVIDENCE_DIR` | 截图与 sidecar 的写入目录（**验收时必需**） | 测试 `skip`，理由写明"未提供证据目录" |
| `SIDE_QUOTE_E2E_PROFILE` | 所连实例的 profile 名；写入 sidecar，作为 AC-12 的隔离身份证据（必须为 `side-quote-verify`） | 已配置证据目录时 `skip`，理由写明缺少 profile 身份 |
| `SIDE_QUOTE_E2E_ALLOW_LIVE` | 显式放行对 `3081` 运行（只在用户明确授权时设为 `1`） | 拒绝在 `3081` 上运行，理由写明"拒绝对 live 端口运行端到端用例" |

规则：

- `skip` **不等于**通过。验收记录必须把 skip 明确写成"未执行"，不得计为 PASS。
- 端口不得为 `3081`（用户 live 实例），除非另有明确授权并设置 `ALLOW_LIVE=1`；默认硬拒绝。
- 夹具（含名为 `.env` 的文件）一律在测试运行时生成到临时目录；仓库内不得出现名为
  `.env` 的文件（仓库硬性禁止提交 `.env`）。浏览器层因 Files 页隐藏 `.` 开头项而改用
  等价敏感名夹具（见 E-05 的环境例外），该替换不影响"敏感名不拦截"的规则本身。
- 截图与断言输出写入 Feature 证据目录
  `wiki/feature-workspace/initiatives/initiative-i001-side-quote/features/feat-i001-f01-text-preview-quote/evidence/`，
  文件名带用例编号与序号；每张截图配同名 `.json` sidecar。
- 每条截图证据必须能对应：Git revision、实例地址与端口、profile、视口尺寸、用例编号。
  启动地址里的 `?token=…` 不得进入证据（sidecar 只记录 origin + path + port）。

### 4.3 人工回归（其他格式零影响）

在同一个 `side-quote-verify` 实例中，按 E-04 的格式逐个打开并截图；结论必须逐格式写
"通过 / 失败 / 不适用"，不得只写"已验证"。

## 6. 由本 Feature 派生的变更义务

必须在实现阶段同批完成，否则 AC-11/AC-12 无法成立：

1. `.factory/factory.yaml` 的 `commands` 新增端到端命令：
   ```text
   node --test "code/test/e2e/**/*.test.mjs"
   ```
   并运行 `factory upgrade` 重新生成 `wiki/governance/workflow-profile.md`，两者放在
   同一次提交。
2. `wiki/code-ai/project-facts.md`：
   - §4「真实命令」补入端到端命令；
   - §5「测试分层」由占位改为本文件 §1 的三层结构（单元 / 端到端 / 人工回归）。
3. `code/package.json`：确认 `files` 不含 `test`，`dependencies` 为空。
4. `code/README.md`：写入 §7 的已知取舍。

## 7. 必须写入 `code/README.md` 的已知取舍

以下条目必须出现在插件 README，作为"已记录、不修好"的取舍：

1. 同一会话内同一文件自第二次引用起只给路径指针，不再重复贴原文；想再贴原文需重新
   引用另一个文件或重启插件。
2. 跨预览体的选区不可引用（按钮置灰），需要分别引用。
3. 敏感判断只看文件名，不做内容特征检测；普通文本里抄写的密钥不会被警示。
4. 引用会把文件内容与工作区相对路径送入会话并发送给模型；对含密钥的文件应自行判断。
5. HTML 预览不支持引用（由 `I001-F02` 的接管式渲染器负责，默认关闭）。
6. 手写 bundle 与本版 DSH 客户端接口强耦合：升级到新 rc 后必须重跑单元层与端到端层，
   责任在本项目，不在 DSH。
7. 截断阈值为固定 200 行 / 8000 字符，不可配置。

## 8. 未执行即不得声称通过

- 端到端测试因缺少外部驱动而 `skip` → 记"未执行"，AC-1/AC-2/AC-5/AC-6/AC-7/AC-8/
  AC-12/AC-13 不得判通过。
- 人工回归未逐格式留档 → AC-13 不得判通过。
- 只跑 `node --check` / `node --test` → 不足以支撑本 Feature 任何浏览器行为结论。
