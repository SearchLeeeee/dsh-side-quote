# I001-F02 可行性结论摘要

- 结论：`Conditionally feasible`（附条件可行）
- 共享约束：[I001 可行性确认约束](../../../feasibility/confirmed-constraints.md)（必读，不得重复论证）
- 依赖：`I001-F01` 提供核心插入与来源组装能力。

## 本 Feature 的成立条件

1. 接管以官方扩展点注册，自带插件包不改、不替换、不卸载；`.html` 之外零影响。
2. 默认关闭：未显式开启时，用户看到的 HTML 预览行为与自带预览一致，且该差异可逆。
3. iframe 保持不透明 origin 与最小权限；桥只传递选区文本与来源信息，不向页面脚本
   暴露宿主对象或会话能力。
4. 页面 CSP 使桥失效、相对资源不可用时，必须给出可判定的降级表现与通知，而不是静默
   无反应。

## 主要难点与负向影响

- 接管后自带 HTML 预览的交互预览、相对资源打包与缩放能力不自动继承，渲染质量需自行
  保证，且差距会随 DSH 升级扩大。
- 框架内允许页面脚本运行，属用户可见的安全姿态变化；风险面只能靠默认关闭与显式开启
  收敛，不能消除。
- CSP 与相对资源在真实文件上的表现是本 Feature 最大的未知项。

## 拆分判断

Scope Gate 总分 13，`split-default`；接管、桥与开关三段互为前提、无法独立验收，
保留理由已写入 `feature.yaml` 的 `scope_gate.indivisibility_reason`。
