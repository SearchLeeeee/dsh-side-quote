# I001 可行性确认约束

> 范围：本文件只记录可行性拷问阶段确认的技术边界、否决方向、前置条件、负向影响与
> 仍待解决的问题。它约束 `I001-F01`、`I001-F02` 的需求讨论，不定义业务细节。
> 环境事实基于本机 DSH `0.2.2-rc.3`（web profile）实机只读核对，记录日期 `2026-11-15`。

## 1. 已确认结论

1. **缺口真实存在。** 自带引用能力只覆盖对话区文本（`conversation.chat.text-interaction`
   的 `quote`），右侧栏文档预览没有任何引用入口。目标闭环为：预览内划词 → 组装带来源
   路径的引用块 → 插入当前会话输入框 → 通知结果。
2. **目标 API 在当前版本存在且可用。**
   - `ctx.conversation.input.for(sessionScope)` 提供 `insertQuote(text, summary)` 与
     `notify('info' | 'error', text)`；`summary` 携带 `label`、`title`、`detail`、`body`，
     足以承载「来源路径 + 文本片段」的可读描述。
   - 会话作用域由 `ctx.sessions.scope(sessionId)` 取得；缺少保留会话时返回空值，必须按
     失败路径处理。
3. **格式扩展有官方位点。** `ctx.documentPreviews.register({ id, extensions, priority })`
   中外部实现优先于自带实现；文档正文通过 `sidebar.right.tab.document`（keyed）注册，
   文件字节由文档属主按 `loading` 模式提供，第三方无需自行读取主文件。
4. **零构建口径。** 宿主只提供 **已构建** 的客户端 bundle，不做编译：`dsh.client` 指向
   的 `lib/client.js` 必须已是 `window.__ModuleLoader__.load({ id, factory(require) })`
   形式，React 等基座模块经 `require()` 从平台模块表解析。因此「零构建」的实现含义是
   **手写该 bundle 格式**（纯 JS、无 JSX、无 TS），不引入构建链，也不新增运行时依赖。
5. **格式验收范围。** 验收接受「预览中可见文字的格式」，不限定 HTML：至少覆盖父 DOM
   渲染的文本类格式（纯文本、markdown、代码），HTML 另走接管路径（见第 3 条结论）。
6. **HTML 接管口径。** 允许通过官方扩展点抢占 `.html` 渲染（插件包本身不改、不替换、
   不卸载），但必须 **默认关闭、仅在用户显式开启时生效**；未开启时用户看到的 HTML
   预览行为与自带预览一致。
7. **隔离边界。** 不写业务项目目录；不重启、不终止用户正在使用的 `dsh web`；端到端
   取证须在独立 profile 与独立端口进行，实验代码不得进入用户 live profile。
8. **敏感面必须显式定规。** 引用会把文件内容与来源路径送入会话并发送给模型，命中
   `local-machine-paths`（路径）与 `credentials`（如 `.env` 内容）两个敏感类别。路径形式
   与内容过滤策略必须在需求讨论中写成显式规则，不得默认「原样全发」。

## 2. 已否决方向

1. **依赖自带 HTML 预览读取选区。** 自带 HTML 预览是不透明 origin 的 sandbox iframe
   （`sandbox="allow-scripts"`，无 `allow-same-origin`），父页面无法访问其文档与选区；
   不接管渲染则 HTML 引用不可行。
2. **修改或替换自带插件包。** 硬约束禁止；接管只能经官方扩展注册实现，且默认关闭。
3. **引入构建链或用 JSX 源码。** 与零构建约束冲突；若采用必须先改约束。
4. **直接把实验版本装进用户 live `web` profile。** 会热更新到用户正在使用的页面。

## 3. 前置条件（不成立则方案不成立）

1. DSH 客户端接口版本锁定与升级回归：`__ModuleLoader__` 引导格式、`ctx.documentPreviews`、
   `ctx.conversation.input`、`ctx.sessions.scope` 均为版本内接口，升级到新 rc 后必须重验。
2. 隔离验收环境可用：独立 profile（由自带 web 模板新建）与独立端口。
3. 端到端证据形式在需求讨论中定案（人工检查单或浏览器自动化），不得以「只跑了
   `node --check` / `node --test`」代替浏览器行为验收。

## 4. 负向影响

1. 接管 `.html` 后不自动继承自带 HTML 预览的交互预览、相对资源打包、缩放等能力；
   渲染质量由本插件自行负责，且与自带实现的差距会随 DSH 升级扩大。
2. 引用携带本地文件内容与路径进入会话，存在把机密文件内容送进模型的现实风险。
3. 手写 bundle 无类型检查与编译期校验，DSH 升级造成的不兼容会表现为静默失效。
4. 核心与接管器集中在同一插件，监听、定时器、iframe、注册项的清理责任集中。

## 5. 仍待讨论解决的开放问题

- 引用路径形式：工作区相对路径还是绝对路径。
- 敏感文件（如 `.env`）的引用策略：拦截、提示后允许，还是原样引用。
- 防抖与去重的具体语义：同一选区重复触发、跨文件切换时的归属。
- HTML 接管的开关入口位置、默认值与关闭后的可逆性验证方式。
- 端到端证据形式与取证环境。
- 相对 CSS/JS 是否打包（技术上有读取通道，但成本与收益待评估）。
