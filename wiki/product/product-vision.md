# 产品目标与稳定需求

> 权威范围：本文件是 dsh-side-quote 产品目标、用户可见能力、明确不做的范围与已确认
> 降级的唯一权威。交互与内容细节在
> [前端契约](../implementation/frontend/sidebar-quote-contract.md)，实现形态在
> [前端实现](../implementation/frontend/sidebar-quote-implementation.md)，验收判定在
> [测试与验收](../testing/sidebar-quote-acceptance.md)。

## 1. 一句话定位

在 DeepSeek Harness Web 的右侧栏文档预览中划词，把选中文字组装成带来源路径的引用块，
插入当前会话输入框的零构建客户端插件。

## 2. 要解决的问题

平台的引用能力只覆盖对话区文本，右侧栏的文档预览没有任何引用入口。用户想引用某个文件
里的一段话时，只能手工抄写正文与路径，既费时又容易丢失来源信息。

## 3. 用户可见能力（稳定需求）

1. **引用按钮**：文本类文档预览的头部出现「引用」按钮。只有同一预览体内存在非空白选区
   时可用，其余情况置灰。
2. **引用块**：点击后把「摘录 + 空行 + `来源：<工作区相对路径>`」插入当前屏幕会话的
   输入框；摘录保真，不重排空白、不加代码围栏。
3. **指针降级**：同一会话内同一文件自第二次引用起改为指针块，只给路径并提示重新读取，
   不再重复贴原文。
4. **敏感名警示**：文件名命中敏感名单时照常插入，并额外给出一条 `info` 警示，由用户
   自行决定是否发送。
5. **通知预算**：插入成功不通知；只有失败发 `error`、敏感名命中发 `info`，一次操作最多
   一条通知。
6. **双语文案**：按钮与通知文案提供中英两套；进入消息正文的内容文案（来源行、截断说明、
   指针文案）不随界面语言变化。
7. **HTML 预览的引用（显式接管）**：`.html` / `.htm` 预览头部提供接管开关，**默认关闭**。
   只有「持久开关为开」且「平台页面脚本闸门为真」时，预览才由本插件渲染，并在预览内提供
   划词引用；关闭态正文仍由自带实现渲染。接管开启时外部 CSS / JS / 图片一律不加载，
   inline 样式与 inline 脚本照常生效。

## 4. 明确不做

- 不做自动插入、不绑快捷键：插入必须由用户显式点击按钮触发。
- 不支持跨预览体选区：选区起点与终点必须落在同一个预览体。
- 不做内容特征级敏感检测：普通文本里抄写的密钥不会被识别。
- 不做全量「会话已读」推断：只认本插件自身的插入记录，不扫描会话历史、不推断 agent 的
  读取行为。
- 不接管输入框组件、不修改或替换或卸载任何自带插件包。
- 不引入构建链、不新增运行时依赖。
- 不写业务项目目录；不为取证触碰用户正在使用的实例与其 profile。
- 接管时不读取、不打包任何相对资源；不支持嵌套 iframe、画布渲染的文字、
  `user-select: none` 的页面内文字。
- 不为接管引入消息令牌或白名单文本校核：页面脚本与桥同 realm，令牌无法防范伪造。

## 5. 已确认的降级与取舍

以下均为新能力内建的边界，不是缺陷，不通过后续「顺手修好」来消除：

| 取舍 | 用户可见后果 | 依据 |
| --- | --- | --- |
| 同一会话同一文件自第二次引用起只给指针 | 想再贴原文需引用另一个文件或重载插件 | 控制同一文件在上下文中的重复成本 |
| 跨预览体选区不可引用 | 需要分别引用两段 | 避免把 B 的文本按 A 的路径写入来源行 |
| 敏感判断只看文件名 | 无敏感名但含密钥的文件不会被警示 | 内容特征检测成本高且误报不可控 |
| 截断固定 200 行 / 8000 字符 | 阈值不可配置 | 上下文成本可预期 |
| 插入成功后焦点回到输入框 | 插件不主动抢焦点，但平台插入通道内部会聚焦 | 平台 `insertQuote` 的固有行为，插件不可阻止 |
| HTML 接管默认关闭 | 用户需显式开启才有 HTML 引用入口 | 接管会改变预览渲染与安全姿态，默认不改变既有行为 |
| 接管要求平台页面脚本闸门为开 | 闸门关闭时开关不可用并说明原因 | 沿用平台对页面脚本的偏好，不由插件绕过 |
| 接管开启时不加载外部 CSS / JS / 图片 | 页面样式、脚本与图片可能缺失 | 交互模式 iframe 无 CSP，允许相对路径等于给页面一个读工作区并外发的出口 |
| 接管开启时停用插件，已打开的预览正文为空直到整页刷新 | 需要用户手动刷新 | 平台侧行为，插件无法让已挂载的预览自动回落 |
| 手动切回自带渲染器时 HTML 引用按钮恒置灰 | 需重新开启接管才能引用 | 头部位点拿不到本 tab 选中的实现 |

## 6. 证据门槛

任何「能力可用」的结论都必须有端到端浏览器证据，不以静态检查或单元层通过代替。验收
分层、环境与判定标准见[测试与验收](../testing/sidebar-quote-acceptance.md)。
